3. Estrategia de Pruebas

3.1 Testing manual

  • Front: criterios de aceptación, flujos de usuario y comparación visual con el diseño (Figma, si el equipo lo usa).
  • API y back: contratos, manejo de errores, códigos de estado e impacto en la base de datos de QA.
  • Integración: flujos completos entre front y servicios cuando la HU lo requiere.

3.2 Testing automatizado

Tests con campo Automatizado = SI, ejecutados en la suite del equipo (en esta guía, Playwright con Page Objects, corrido por GitHub Actions). Los resultados se registran en Test Executions asociadas a este plan.
